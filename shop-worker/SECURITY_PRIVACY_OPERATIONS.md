# Shop security and privacy operations

The storefront edge route adds security headers and exposes only approved static paths. It excludes backend/configuration sources and removes DRAFT records and non-public fields from public catalog responses. Canonical catalog records remain unchanged in GitHub; the commerce Worker reads that source through the authenticated GitHub API.

Deploy API with `wrangler.toml`, Admin with `wrangler.admin.json` after running its allowlist builder, and storefront protection with `wrangler.storefront.toml`. Keep the API's 15-minute scheduled reconciliation trigger. Never deploy development snapshots or publish local credentials. Provision LOGIN_IP_PEPPER as a randomly generated Worker secret with at least 32 characters; do not put it in source or public configuration. The live API fails closed for login/newsletter IP pseudonymisation if it is missing. Existing historical IP checksums are not improved retrospectively.

Customer sessions use HttpOnly/Secure/SameSite cookies only. Legacy customer bearer authentication is rejected and browser tokens are removed. API mutations require a trusted Origin. Admin passkey sessions are capped at 24 hours from creation, including previously issued longer sessions. Lost devices can be revoked through the existing device management.

Visitor statistics require an explicit optional consent decision, respect DNT/GPC, stop on revocation and do not read cart storage before consent. The API ignores events without the current consent marker. Essential cart, login and checkout remain independent of that choice. The public consent choice expires after 180 days; existing event retention remains 30 days.

Privacy requests are accessible only to authenticated Admin users. Review pending requests promptly; the displayed regular deadline is one calendar month, without a case-specific justified extension. Send the response through an authorised communication channel, explain any lawful retention and record the response time and note. Only then explicitly complete a deletion request. Completion atomically removes optional saved account addresses, sessions, login links and account identifiers. Order contact snapshots, invoices, payment/refund/withdrawal evidence and archived confirmations remain unchanged. Newsletter and provider records must be assessed separately. Deployment and migration do not complete requests or delete account/customer records.

Newsletter unsubscribe and consent retention are separate tasks. Review expired pending applications and unsubscribed consent proofs, including records with old IP hashing, against actual legal claims and retention requirements. Remove expired non-required personal records through a reviewed operator process and the email provider. No destructive bulk cleanup is automatically enabled by this change.

`config/legal-content.json` is the reviewed canonical DE/EN/FR source. `scripts/sync_legal_content.py` generates browser and Worker copies and embeds the browser constants in the existing app bundle without an extra blocking request; `build_site.py` invokes it. New contract confirmations include the full terms and withdrawal form in HTML and plain text and are archived with the existing immutable hashes. Previously archived confirmations remain unchanged.

The edge enforces frame/object/base restrictions and uses the full script policy in report-only mode. Before making script restrictions blocking, test PayPal, supported Apple Pay devices, Turnstile, account login and opt-in/withdrawal in real supported browsers. No production purchase, payment, refund, customer email or label is performed by the synthetic tests.

Outstanding operator obligations: packaging registration, system participation and quantity reporting; verified business phone and delivery promises; data-processing agreements and international-transfer safeguards; product-safety information/proof where required; a documented BFSG exemption or accessibility assessment; image rights; separate review of rental contracts. Software or passing tests do not certify legal compliance.
